# Hello World Frontend Stack Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Scaffold a greenfield "hello world" React repo where every stack library is installed, configured, and visibly exercised by a sortable users-table demo fed by MSW-mocked, Zod-validated network requests — with light/dark theming built in.

**Architecture:** A Vite SPA with TanStack Router file-based routes (`__root.tsx` is the atomic-design *template*, route files are *pages*). The `UsersTable` organism owns its `useQuery` call; its `queryFn` Zod-parses the response so all downstream code sees trusted `User[]`. One MSW handlers module is reused by four consumers: the dev browser worker, Vitest's Node server, the Storybook MSW addon, and Playwright (which rides the dev server's browser worker). Theming is class-driven (`dark` on `<html>`) through shadcn's CSS variables, so components — including Base UI portal content — theme themselves via semantic tokens.

**Tech Stack:** Node ≥24 / npm, React 19, TypeScript (latest, strict), Vite 8, Tailwind CSS v4 (`@tailwindcss/vite`), shadcn/ui CLI v4 (Base UI primitives — no Radix), TanStack Router v1 + Query v5 + Table v8, Zod v4, Biome 2, MSW 2, Vitest 4 + React Testing Library (jsdom), Storybook 10 (`@storybook/react-vite` + msw-storybook-addon v3), Playwright.

**Spec:** `docs/superpowers/specs/2026-08-12-hello-world-stack-design.md` (amended 2026-08-12: theming + version refresh)

## Global Constraints

- Install the **latest stable** of every dependency (`@latest`); majors verified current on 2026-08-12: Vite 8, @vitejs/plugin-react 6, Storybook 10.5, shadcn CLI 4, msw-storybook-addon 3, Vitest 4, Zod 4.4, Biome 2.5, MSW 2.15, TanStack Router 1.170.x. Local Node is v26.5.0 — satisfies the `>=24` engines floor.
- **Biome 2 is the sole linter/formatter.** No ESLint or Prettier configs, deps, or scripts may remain anywhere.
- **Tailwind v4 is CSS-first:** configured via `@tailwindcss/vite` + `@import "tailwindcss"` in CSS. Never create `tailwind.config.js`.
- `src/routeTree.gen.ts` is generated by the Router Vite plugin, **committed to git**, and **excluded from Biome**.
- `@tanstack/react-router` and `@tanstack/router-plugin` version independently — install both `@latest`, never pin them to one shared version string.
- TypeScript **strict mode** stays on; `@/` path alias → `src/` (tsconfig *and* Vite resolve alias). The alias MUST exist before `shadcn init` runs — the v4 CLI does not edit tsconfig/vite config and hard-fails at preflight without it.
- `src/components/ui/` is a vendor layer (shadcn CLI output): Biome linting disabled for it (formatting still applies), stories beside it stay linted. Never hand-edit generated component files; re-running `npx shadcn add` may overwrite them. The `shadcn` package itself is a **runtime dependency** in v4 (`src/index.css` does `@import "shadcn/tailwind.css"`) — do not remove it.
- **Theming:** the `dark` class goes on `<html>` (documentElement) only — never a nested wrapper — so Base UI portal content (menus, dialogs) stays themed. Components use semantic tokens (`bg-background`, `text-foreground`, `text-destructive`, …), never hardcoded palette utilities.
- Handwritten components live flat inside their level folder with story (and test, where defined) side by side: `src/components/{atoms,molecules,organisms}/Name.tsx`, `Name.stories.tsx`, `Name.test.tsx`.
- Story titles mirror the taxonomy exactly: `UI/…`, `Atoms/…`, `Molecules/…`, `Organisms/…`.
- Storybook: never install `@storybook/addon-essentials`, `@storybook/addon-interactions`, `@storybook/blocks`, or `@storybook/test` — none has a ≥9 release; their `latest` tags pull Storybook 8 packages that break the build.
- Required npm scripts (exact names): `dev`, `build`, `test`, `test:e2e`, `lint`, `format`, `check`, `storybook`, `build-storybook`.
- `User` schema fields: `id`, `name`, `email`, `status` ∈ `active | invited | suspended`. `type User = z.infer<typeof UserSchema>` is the single source of type truth.
- MSW serves `GET /api/users` from a 10-user fixture with a ~500 ms artificial delay.
- Commit at the end of every task. Work directly on `main` (greenfield repo).

**Locked design decisions:**
1. The spec's testing section says the `UsersTable` story "fetches through the MSW addon" and the Vitest test integrates "Query + MSW + Zod" — therefore `UsersTable` (organism) owns the `useQuery` call and the pending/error/success mapping. The `/users` page is a thin wrapper.
2. Theming (user-approved 2026-08-12): `ThemeProvider` in `src/lib/theme.tsx` (`'light' | 'dark' | 'system'`, localStorage key `ui-theme`, system default), Sun/Moon `ThemeToggle` molecule in `AppHeader`, Storybook light/dark toolbar, Vitest + Playwright coverage. No FOUC script, no live OS-change listener, no extra named themes.
3. Versions (user-approved 2026-08-12): latest majors — Vite 8, Storybook 10, shadcn v4 with **Base UI** primitives (Radix dropped).

- [ ] **Step 2: Configure**

Replace `biome.json` with (keep the exact `$schema` URL that `init` emitted). Syntax notes verified against Biome 2.5: `rules.preset` replaces the deprecated `rules.recommended: true`; `files.includes` must lead with `"**"` (a negation first trips `noBiomeFirstException`); the exclusion is a file glob, so no trailing `/**`:

```json
{
  "$schema": "<keep the schema URL emitted by biome init>",
  "vcs": { "enabled": true, "clientKind": "git", "useIgnoreFile": true, "defaultBranch": "main" },
  "files": { "includes": ["**", "!src/routeTree.gen.ts"] },
  "formatter": { "enabled": true },
  "linter": { "enabled": true, "rules": { "preset": "recommended" } },
  "assist": { "enabled": true, "actions": { "source": { "organizeImports": "on" } } },
  "overrides": [
    {
      "includes": ["src/components/ui/**", "!src/components/ui/*.stories.tsx"],
      "linter": { "enabled": false }
    }
  ]
}
```

Rationale: `vcs.useIgnoreFile` makes Biome respect `.gitignore` (skips `dist/`, `node_modules/`, `storybook-static/`); the override treats shadcn output as generated code (spec calls it a vendor layer) while stories beside it stay linted; `routeTree.gen.ts` exclusion is required by the spec (its generated header carries eslint/ts-nocheck pragmas but nothing Biome understands).

`src/lib/theme.tsx` — the canonical shadcn Vite pattern, trimmed to what the spec needs:

```tsx
import {
  createContext,
  useContext,
  useEffect,
  useState,
  type ReactNode,
} from 'react'

export type Theme = 'light' | 'dark' | 'system'

interface ThemeContextValue {
  theme: Theme
  resolvedTheme: 'light' | 'dark'
  setTheme: (theme: Theme) => void
}

const STORAGE_KEY = 'ui-theme'

const ThemeContext = createContext<ThemeContextValue | undefined>(undefined)

function getSystemTheme(): 'light' | 'dark' {
  return window.matchMedia('(prefers-color-scheme: dark)').matches
    ? 'dark'
    : 'light'
}

export function ThemeProvider({ children }: { children: ReactNode }) {
  const [theme, setThemeState] = useState<Theme>(
    () => (localStorage.getItem(STORAGE_KEY) as Theme | null) ?? 'system',
  )

  const resolvedTheme = theme === 'system' ? getSystemTheme() : theme

  useEffect(() => {
    document.documentElement.classList.toggle('dark', resolvedTheme === 'dark')
  }, [resolvedTheme])

  const setTheme = (next: Theme) => {
    localStorage.setItem(STORAGE_KEY, next)
    setThemeState(next)
  }

  return (
    <ThemeContext.Provider value={{ theme, resolvedTheme, setTheme }}>
      {children}
    </ThemeContext.Provider>
  )
}

export function useTheme() {
  const context = useContext(ThemeContext)
  if (!context) {
    throw new Error('useTheme must be used within ThemeProvider')
  }
  return context
}
```

- [ ] **Step 3: Implement UsersTable**

`src/components/organisms/UsersTable.tsx` — split into two components because React hooks can't sit below early returns: the outer one maps Query state, the inner one calls `useReactTable`:

```tsx
import { useQuery } from '@tanstack/react-query'
import {
  type ColumnDef,
  type SortingState,
  flexRender,
  getCoreRowModel,
  getSortedRowModel,
  useReactTable,
} from '@tanstack/react-table'
import { useState } from 'react'
import { Spinner } from '@/components/atoms/Spinner'
import { StatusBadge } from '@/components/atoms/StatusBadge'
import { SortableColumnHeader } from '@/components/molecules/SortableColumnHeader'
import {
  Table,
  TableBody,
  TableCell,
  TableHead,
  TableHeader,
  TableRow,
} from '@/components/ui/table'
import { fetchUsers } from '@/lib/api'
import type { User } from '@/schemas/user'

const columns: ColumnDef<User>[] = [
  {
    accessorKey: 'name',
    header: ({ column }) => (
      <SortableColumnHeader column={column}>Name</SortableColumnHeader>
    ),
  },
  {
    accessorKey: 'email',
    header: ({ column }) => (
      <SortableColumnHeader column={column}>Email</SortableColumnHeader>
    ),
  },
  {
    accessorKey: 'status',
    header: 'Status',
    cell: ({ row }) => <StatusBadge status={row.original.status} />,
  },
]

export function UsersTable() {
  const query = useQuery({ queryKey: ['users'], queryFn: fetchUsers })

  if (query.isPending) return <Spinner />
  if (query.isError) {
    return (
      <p role="alert" className="text-destructive">
        Could not load users: {query.error.message}
      </p>
    )
  }
  return <SortableUsersTable users={query.data} />
}

function SortableUsersTable({ users }: { users: User[] }) {
  const [sorting, setSorting] = useState<SortingState>([])
  const table = useReactTable({
    data: users,
    columns,
    state: { sorting },
    onSortingChange: setSorting,
    getCoreRowModel: getCoreRowModel(),
    getSortedRowModel: getSortedRowModel(),
  })

  return (
    <Table>
      <TableHeader>
        {table.getHeaderGroups().map((headerGroup) => (
          <TableRow key={headerGroup.id}>
            {headerGroup.headers.map((header) => (
              <TableHead key={header.id}>
                {header.isPlaceholder
                  ? null
                  : flexRender(header.column.columnDef.header, header.getContext())}
              </TableHead>
            ))}
          </TableRow>
        ))}
      </TableHeader>
      <TableBody>
        {table.getRowModel().rows.map((row) => (
          <TableRow key={row.id}>
            {row.getVisibleCells().map((cell) => (
              <TableCell key={cell.id}>
                {flexRender(cell.column.columnDef.cell, cell.getContext())}
              </TableCell>
            ))}
          </TableRow>
        ))}
      </TableBody>
    </Table>
  )
}
```
